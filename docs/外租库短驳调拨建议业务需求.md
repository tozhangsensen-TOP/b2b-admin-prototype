# 外租库短驳调拨建议业务需求

版本：V1.0  
适用场景：石家庄试点，后续可扩展至其他本库/外租库组合  
需求类型：业务侧需求提报，面向大数据/IT评估与排期，不作为页面PRD

## 1. 业务背景

目前本库受库容限制，部分库存存放在外租库。石家庄业务需要根据本库库存、外租库库存、销量周转、次日到货预约、叉车/上架产能、库容水位与车辆装载约束，提前生成外租库短驳调拨计划，将外租库库存转入本库，保障本库发运与分拣作业连续。

现有外租库转拨建议原型已具备“系统生成建议、人工确认、调整实际数量、提交转拨单”的基础方向，但仍需要补齐石家庄短驳业务规则：每日固定时点计算、7天安全周转、次日到货剔除、产能与库容校验、整托/整车约束、车次拆分与通知外租库执行。

## 2. 业务目标

1. 从人工经验判断转为系统化生成调拨建议，减少漏调、错调和临时补货。
2. 保证本库周转不足SKU优先被识别，支撑次日分拣、发运和补货。
3. 调拨数量需同时满足库存缺口、外租库可供、库容可接收、收货上架产能、整托整车等约束。
4. 输出可执行的调拨计划和车次安排，便于外租库提前备货、本库安排收货上架。
5. 保留人工确认和调整入口，避免系统建议直接落单造成现场不可承接。

## 3. 业务范围

### 3.1 V1纳入范围

- 石家庄本库与对应外租库之间的短驳调拨建议。
- 每日固定时间生成调拨建议，支持人工手动触发补算。
- 按SKU识别本库周转不足，生成候选SKU池。
- 对候选SKU进行次日到货、作业产能、库容、外租库库存、整托和车辆装载校验。
- 生成调拨建议明细，支持业务人员确认、调整实际调拨数量、删除或补充SKU。
- 确认后形成正式调拨计划/转拨单，并可按车次拆分给外租库执行。

### 3.2 V1不纳入范围

- 基于历史销售模型的复杂预测调参。
- 多外租库自动选仓与跨外租库拼车优化。
- 全自动审批后无人工确认直接落单。
- 精细化运费优化模型。
- PDA/PC具体页面交互细节。

## 4. 核心业务流程

1. 每日约15:00启动外租库短驳调拨计算。若当日无到货预约或到货数据已确认完整，则进入计算。
2. 系统获取SKU维度的本库库存、外租库可用库存、周均销量、日均销量、每托件数、外库可供托数、次日到货预约、当前库容水位与次日预计出库/入库托数。
3. 计算本库周转天数，低于7天的SKU进入候选SKU池；周转天数大于等于7天的SKU不建议调拨。
4. 对候选SKU进行次日到货校验。若该SKU次日9:00前有足量到货计划，剔除出调拨候选；若无到货计划或到货不足，继续校验。
5. 计算缺口件数，并按码托规格向上取整为整托；调拨托数不得超过外租库可供托数。
6. 将全部候选SKU产生的新增收货/上架托数，与本库既有作业量叠加，校验是否超过叉车收货上架峰值。
7. 校验库容是否可承接。预计库容使用率原则上不超过85%，需结合次日到仓、历史周平均出库托数、当前库容占用、在途调拨占用进行出入平衡判断。
8. 若产能或库容不满足，系统需削减或调整调拨托量，优先保留发运缺口SKU，非紧急补库SKU延后。
9. 根据整车装载规则进行车次建议。石家庄场景可优先参考16托整车；不足整车时允许业务人工决定是否半车发、延后或补入低优先级SKU凑车。
10. 业务人员确认建议后，系统生成正式调拨计划/转拨单，并通知外租库按车次和要求到货时间执行。

## 5. 调拨建议计算规则

### 5.1 候选SKU识别

本库周转天数 = 本库可用库存 / 日均销量。  
日均销量可由周均销量折算：日均销量 = 周均销量 / 7。  
当本库周转天数小于7天时，SKU进入候选池；当本库周转天数大于等于7天时，不生成调拨建议。

### 5.2 缺口计算

基础缺口件数 = 7 × 日均销量 - 本库当前可用库存。  
如业务确认纳入在途或次日到货，则调整为：

调整后缺口件数 = 7 × 日均销量 - 本库当前可用库存 - 次日9:00前可用到货量 - 已确认在途调拨量。

缺口小于等于0时，不建议调拨。缺口大于0时，进入托数转换。

### 5.3 整托转换

建议调拨托数 = 向上取整（缺口件数 / 每托件数）。  
最终调拨件数 = 建议调拨托数 × 每托件数。  
最终调拨托数不得超过外租库可供托数；如外租库不足，则以外租库可供托数为上限。

### 5.4 次日到货剔除

若候选SKU在预约系统中存在次日9:00前全部到货计划，且到货数量能够覆盖安全周转缺口，则该SKU不再建议短驳。  
若到货时间晚于9:00、到货数量不足、预约未确认或数据缺失，则保留该SKU，并在建议中标记原因。

### 5.5 作业产能约束

调拨新增的收货/上架托数，需要叠加次日已有收货、补货、上架作业量后进行校验。  
石家庄参考产能：干库约300托/日，冻库峰值约150托/日。最终阈值以仓库确认后的配置为准。

若超过产能，系统需按优先级削减调拨托量。建议优先级为：发运缺口SKU > 安全库存缺口SKU > 凑车补库SKU。

### 5.6 库容约束

预计库容使用率 = 当前库容使用率 + 次日到仓占用 + 本次调拨建议占用 - 预计出库释放。  
本次建议后预计库容使用率原则上不超过85%。若超过阈值，系统需减少调拨量或提示人工确认。

### 5.7 整车与车次规则

系统需将确认后的调拨建议按车次拆分，展示每车的托数、件数、方数和SKU明细。  
石家庄可参考16托为整车装载目标。短期先支持人工勾选明细行生成车次，底部实时汇总托数、件数、方数；长期支持系统自动排线和自动凑车。

## 6. 数据需求

### 6.1 输入数据

- SKU主数据：SKU编码、名称、规格、每托件数、体积/方数、温层、库区、是否可整托调拨。
- 本库库存：当前可用库存、冻结库存、在途库存、批次库存、库位/库区库存。
- 外租库库存：外租库可用库存、可供托数、批次、库存状态。
- 销量数据：周均销量、日均销量、近7天/近30天销量口径。
- 订单/发运数据：未来待发运量、次日分拣需求、历史周平均出库托数。
- 到货预约：次日到货SKU、到货数量、预计到货时间、是否9:00前到货、预约确认状态。
- 作业产能：干库/冻库收货上架峰值、已排作业托数、可用叉车/人员产能。
- 库容数据：当前库容使用率、库区容量、预计入库占用、预计出库释放、库容阈值。
- 车辆/装载数据：车型、满载托数、方数、单车限制、承运线路。

### 6.2 输出数据

- 调拨建议单：建议单号、生成时间、生成方式、状态、建议总托数、建议总件数、涉及SKU数。
- 调拨建议明细：SKU、本库库存、外租库库存、周均销量、周转天数、缺口件数、建议托数、建议件数、实际确认数量、建议原因。
- 校验结果：次日到货校验、产能校验、库容校验、外库可供校验、整车装载校验。
- 车次计划：车次号、车辆/车型、计划托数、计划件数、计划方数、预计到货时间、外租库备货要求。
- 下游单据：确认后生成转拨单或调拨计划，传递给WMS/仓内执行系统。

## 7. 人工确认与权限

系统建议必须经过业务人员确认后才能生成正式调拨计划。确认人可调整实际调拨数量、删除不需要调拨的SKU、补充临时需要调拨的SKU，并选择或拆分车次。

建议权限如下：

- 仓库计划/库存计划：查看建议、调整数量、确认生成调拨计划。
- 仓库主管：处理超过库容/产能阈值的例外确认。
- 系统管理员：维护参数，如安全周转天数、库容阈值、产能阈值、整车托数、计算时间。
- 外租库作业人员：接收已确认车次计划，不参与建议计算。

## 8. 异常处理

1. 外租库库存不足：按外库可供上限生成建议，并标记“外库不足”。
2. 到货预约数据缺失：不得直接剔除SKU，需保留候选并提示人工确认。
3. 库容超过阈值：系统自动削减非紧急SKU，仍超限时提交主管确认。
4. 作业产能超过阈值：按优先级削减调拨托数，或拆分到下一车次/下一日。
5. 实发少于计划：记录差异，必要时生成二次调拨建议。
6. 本库收货差异或破损：复用现有收货差异流程，并回写调拨建议执行结果。

## 9. 参数配置

V1需支持以下业务参数配置：

- 安全周转天数：默认7天。
- 每日计算时间：默认15:00。
- 次日到货剔除截止时间：默认次日9:00。
- 库容使用率上限：默认85%。
- 干库作业峰值：默认300托/日。
- 冻库作业峰值：默认150托/日。
- 整车目标托数：默认16托。
- 预测销量口径：默认周均销量折算日均销量。

## 10. 验收口径

1. 系统能在每日15:00生成石家庄外租库短驳调拨建议。
2. 本库周转天数大于等于7天的SKU不会进入建议；小于7天的SKU能进入候选并计算缺口。
3. 次日9:00前有足量到货的SKU能被剔除；到货不足或无预约的SKU能保留。
4. 调拨数量能按每托件数向上取整，且不超过外租库可供托数。
5. 建议总托数能校验干库/冻库作业峰值与库容85%阈值。
6. 业务人员能调整实际调拨数量，确认后生成正式调拨计划/转拨单。
7. 调拨计划能按车次输出托数、件数、方数汇总，支持人工勾选明细行排车。
8. 已确认、已取消、待确认建议应能追踪状态，并保留确认人和确认时间。

## 11. 分期建议

### V1：半自动建议 + 人工确认

实现每日计算、候选SKU识别、核心校验、建议确认、车次人工拆分、转拨单生成。

### V2：策略增强

引入销售预测准确率、SKU周转等级、更多在途数据、异常补差、装载率分析。

### V3：自动排线

支持多外租库、多车型、自动凑车、自动排线和运输成本优化。

## 12. 待业务确认事项

1. 石家庄安全周转是否统一按7天，是否存在温层或SKU差异。
2. 周均销量取数口径：近7天、近4周均值，还是剔除异常日后的均值。
3. 次日9:00前到货计划是否一定可用，预约数据是否完整可信。
4. 干库300托、冻库150托是否作为系统默认阈值。
5. 库容85%是否为硬阈值，超过后是否允许主管例外放行。
6. 16托整车是否适用于所有车型，半车发运的审批口径是什么。
7. 确认后下游生成的是转拨单、调拨计划，还是运输车次单与转拨单同时生成。
