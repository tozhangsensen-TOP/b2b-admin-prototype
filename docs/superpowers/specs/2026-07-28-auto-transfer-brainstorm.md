# 自动外库调拨本库 — 会议讨论稿

> 场景：本库库存不足时，系统自动从外租库生成调拨建议单转入本库。
> 本文梳理需要现场拍板的决策点，覆盖需求预测、库容、频率、运费、异常、效果度量等维度。
> 每个点给出"默认建议"和"待决策"两个标记，会议时按默认走或临时推翻。

---

## 一、需求预测逻辑（调拨的数据源）

### 1.1 输入数据源

| 编号 | 数据源 | 说明 | 默认建议 |
|------|--------|------|----------|
| A | 已确认订单的待发运量 | 已下单未发货，按 SKU 汇总未来 N 天需求 | ✅ V1 纳入，主输入 |
| B | 历史销售预测 | 按 SKU 历史日均 × N 天，覆盖更远期 | ⏸ V2 纳入，V1 不做 |
| C | 排产/采购在途计划 | 按生产下线/到货时间表，准确但依赖上游系统 | ⏸ V2 纳入，V1 不做 |
| D | 目标安全库存水位 | 本库低于某水位即补，与发运无关，纯补库 | ✅ V1 纳入，次要输入 |

**待决策**：
- 是否同意 V1 只做 A + D，B/C 推到 V2？
- 历史销售预测（B）如果 V1 就要做，需要多少历史数据？数据源在哪？

### 1.2 预测窗口

- 默认窗口：未来 **3 天**
- 按 SKU 销售周期分级（可选）：
  - 快周转 SKU（饮料、零食等）：1 天
  - 中周转 SKU（保健品、个护）：3 天
  - 慢周转 SKU（家居、宠物用品）：7 天

**待决策**：
- 统一 3 天，还是按 SKU 分级？
- 分级的话，SKU 的周转等级由谁维护？是否需要系统按历史自动打标？

### 1.3 预测准确性度量

- 是否在 V1 就回看历史预测准确率（实际需求 vs 预测值）？
- 是否需要展示置信度标签（高/中/低）给确认人参考？
- 偏差大时：人工修正，还是系统自动调参？

**待决策**：
- V1 是否需要"预测准确率"看板？
- 准确率统计口径：按 SKU、按建议单、按日？

### 1.4 建议数量公式

现设计文档公式：

```
建议数量 = MAX(0, 发运需求 - 本库库存) + 补库量（若外库还有库存）
```

补充细化：

```
缺口 = MAX(0, 发运需求 - 本库现有库存 - 本库在途库存)
补库量 = MAX(0, 目标安全库存 - 本库现有库存 - 本库在途库存 - 已补缺口)
建议数量 = MIN(缺口 + 补库量, 外库可用库存, 本库可接收库容)
```

**待决策**：
- "本库在途库存"（已下采购单未到货）是否纳入扣减？
- "目标安全库存"按 SKU 配置还是按 SKU+库区配置？

## 二、库容约束

### 2.1 库容数据来源

- 本库当前可用库容，按什么单位计算？
  - 方案 A：按方数（m³）
  - 方案 B：按托盘数
  - 方案 C：按 SKU 类型的库区划分（如饮品区、保健品区分别统计）
- 是否需要预留当日其他入库占用（如生产下线、采购到货）？

**待决策**：
- 库容单位选哪个？
- 是否需要"预留库容"概念？预留多少由谁配置？

### 2.2 阈值配置

- 安全水位：80% 预警、90% 禁止再转入（默认值）
- 阈值判断口径：
  - 实时占用率
  - 今日预计占用率（含已计划入库）
- 是否按库区分级设置（如饮品区 85%、保健品区 75%）？

**待决策**：
- 阈值默认值是否合适？
- 按库区分级还是全局统一？
- 阈值由仓库主管配置还是系统硬编码？

### 2.3 冲突优先级（关键决策点）

场景：库容已到 90%，但发运需求 + 满载凑货同时存在，怎么权衡？

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | 优先满足发运需求，放弃满载凑货 | 保证发运，简单 | 装载率低，运费贵 |
| B | 优先满载凑货，多余库存暂缓发运 | 运费便宜 | 可能耽误发运 |
| C | 发运必须满足，满载凑货按"是否触发安全水位"动态判断 | 兼顾两者 | 逻辑复杂 |

**待决策**：
- 默认策略选哪个？建议 C，现场是否认可？
- 库容不够时，是"减少调拨量"还是"完全不调拨"？

### 2.4 库容不够时的处理

- 系统自动降量（按比例分配到各 SKU）
- 系统标记"库容不足"，人工决定是否调整
- 部分调拨 + 剩余延后到下一班次

**待决策**：
- 选哪种？还是组合？

## 三、转运频率策略

### 3.1 频率选项

| 方案 | 描述 | 适用 |
|------|------|------|
| 每日 1 次 | 固定班次，简单 | 需求平稳、压力小 |
| 每日 2 次 | 上下午各一次 | 兼顾响应和成本（推荐默认） |
| 按需触发 | 达到阈值才发 | 经济但波动大 |
| 应急触发 | 紧急订单单独加发 | 突发场景 |

**待决策**：
- 默认频率选哪个？建议"每日 2 次"（如 08:00 / 14:00）
- 是否需要"应急触发"机制？触发条件是什么？

### 3.2 频率与策略的对应

- 多次少量：优先满足次日发运，装载率可能低
- 少次多量：优先满载，响应慢

**待决策**：
- 立场倾向哪边？还是按 SKU 紧急度动态切换？

### 3.3 作业承受度

- 收货组、上架组的峰值承受能力是多少托/方/小时？
- 是否有"夜间收货、白天上架"分时模式？

**待决策**：
- 仓库现场提供峰值数据
- 是否纳入分时模式？

## 四、运费与车辆装载

### 4.1 车型矩阵

需要仓库/承运商提供本库常用车型清单：

| 车型 | 载重(t) | 方数(m³) | 适用场景 |
|------|---------|----------|----------|
| 4.2米 | ? | ? | 小批量、城市内 |
| 6.8米 | ? | ? | 中等批量 |
| 9.6米 | ? | ? | 大批量 |
| 12米  | ? | ? | 大批量、跨城 |

**待决策**：
- 提供车型清单和载重/方数上限
- 本库实际常用的车型是哪几种？

### 4.2 装载单位换算

- SKU 的"件 → 方 → 托"换算关系是否有现成数据？
- 排车按"托"为单位（简化）还是按"方数"（精细）？

**待决策**：
- 选哪个单位？
- 换算系数维护在 SKU 主数据里？

### 4.3 凑满载逻辑

数量不够满载时的策略：

| 方案 | 描述 |
|------|------|
| A | 拉其他低优先级 SKU 凑货（补库型 SKU） |
| B | 等下一班次 |
| C | 直接半载发 |

- 凑货的"成本-收益"门槛：装载率低于多少不发？
  - 默认建议：60%

**待决策**：
- 默认选哪个？建议 A + 60% 门槛
- 凑货时优先拉哪类 SKU？（建议：补库型、慢周转）

### 4.4 短驳排线

- 多个外租库 → 本库 是否拼一车？
- 还是一仓一车？
- 路线规划由承运商决定还是系统建议？

**待决策**：
- V1 单外库还是多外库？
- 多外库时是否拼车？

### 4.5 运费数据

- 是否需要系统计算"单趟运费"和"单位成本"展示给确认人？
- 还是不算运费，只看装载率？

**待决策**：
- V1 是否需要运费计算？还是只看装载率？
- 运费标准（每车型单价）由谁提供？

### 4.6 运费 vs 库容 优先级

极端情况：库容不够 + 装载率低，怎么处理？

- 方案 A：优先库容，装载率再低也少装
- 方案 B：优先满载，库容溢出暂存缓冲区
- 方案 C：库容不够时降级处理（如只发必需 SKU，其他延后）

**待决策**：
- 默认策略选哪个？建议 A

## 五、补充维度（容易遗漏）

### 5.1 批次管理

- 外库库存可能有多个批次，转入本库时批次是否保留？
- 批次先进先出怎么执行？
- 现 `transfer-dispatch.ts` 已支持多批次追溯，是否复用？

**待决策**：
- 批次是否保留？
- FIFO 按 SKU 全局，还是按 SKU+库区？

### 5.2 异常处理

- 外库实发量 < 应发量（缺货）怎么办？
- 本库收货时发现破损/差异怎么办？
- 是否走现成的差异处理流程？

**待决策**：
- 异常是否复用现有差异流程？
- 是否需要"二次调拨"补差？

### 5.3 触发时机

- 现设计：每天 08:00 定时跑
- 是否需要"实时触发"（如某 SKU 本库库存 < 安全水位，立即生成建议）？
- 手动触发权限范围？

**待决策**：
- 是否增加实时触发？
- 手动触发权限给谁？

### 5.4 确认人 / 审批流

- 谁有权确认调拨建议？
- 单级审批还是多级？
- 金额超过多少需要主管审批？

**待决策**：
- 审批流单级还是多级？
- 阈值是多少？

### 5.5 效果度量（KPI）

| KPI | 说明 | V1 是否做 |
|-----|------|-----------|
| 调拨建议采纳率 | 已确认 / 已生成 | ✅ |
| 预测准确率 | 实际需求 vs 预测值 | ⏸ V2 |
| 装载率 | 实际装载 / 车辆方数 | ✅ |
| 调拨响应时长 | 建议生成 → 货物到库 | ✅ |
| 库存周转改善 | 调拨前后本库周转天数 | ⏸ V2 |

**待决策**：
- V1 做哪几个 KPI 看板？

### 5.6 多外库优先级

- V3 提到多外库，V1 单外库时就要预留接口
- 实际是"一个外租库"还是"多个但 V1 只接一个"？
- 多外库时优先级规则（距离、库存量、运费、关系）？

**待决策**：
- 现状是单外库还是多外库？
- 多外库优先级规则先定框架还是 V3 再定？

## 六、会议节奏建议

1. **第一块（必谈）**：数据源 + 预测窗口 → 决定输入边界
2. **第二块（必谈）**：库容阈值 + 优先级 → 决定约束条件
3. **第三块（必谈）**：频率 + 车型 + 满载 → 决定输出形态
4. **第四块（可延后）**：异常 + 审批 + KPI → 决定边界场景

前 3 块是必须当场拍板的，第 4 块如时间不够可列入下次。
