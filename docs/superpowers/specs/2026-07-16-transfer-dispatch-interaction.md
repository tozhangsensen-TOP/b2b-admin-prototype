# 调拨作业中心 — 交互设计

## 1. 概述

整合仓 → 配送仓的调拨场景。同一 SKU + 批次的调拨单自动合并为一个任务，叉车司机在 PDA 上逐库位下架，下架时顺序分播到各目标仓，全程批次可追溯。

### 角色

| 角色 | 设备 | 职责 |
|------|------|------|
| PC 操作员 | PC Web | 查看合并任务、绑定司机、监控执行进度 |
| 叉车司机 | PDA | 领取任务、库位下架、按仓分播确认 |

### 核心流程

```
调拨单 (A仓300、B仓400、C仓300，同 SKU+批次)
  → PC 自动合并为 1 个任务
  → 绑定司机 (刘海峰)
  → PDA 任务总览
  → 逐库位操作：
      ① 扫描库位 → 输入下架数量
      ② 顺序分播：这批分到哪个仓？→ 输入数量 → 确认
      ③ 自动跳到下一个仓 → 直到全部分完
  → 全部库位完成 → 任务结束
```

## 2. 数据模型

### TransferOrderRow

一行 = 一个目标仓的一个 SKU。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 调拨单号 |
| sourceWarehouse | string | 出库仓（整合仓） |
| targetWarehouse | string | 目标配送仓 |
| sku | string | SKU 编码 |
| skuName | string | SKU 名称 |
| batchNo | string | 批次号 |
| plannedQty | number | 计划数量 |
| unit | string | 单位 |
| priority | "高"\|"中"\|"低" | 优先级 |
| requiredArrival | string | 到仓要求时间 |
| status | TransferOrderStatus | 待合并/已合并/执行中/已完成 |

### CombinedTask

合并后的任务，包含多个库位批次来源和多个分播目标。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 任务 ID |
| taskNo | string | 任务编号，如 `CT-面粉-20260716-01` |
| sourceWarehouse | string | 出库仓 |
| sku | string | SKU 编码 |
| skuName | string | SKU 名称 |
| unit | string | 单位 |
| pickLocations | PickLocation[] | 下架来源（多个库位×批次） |
| destinations | TaskDestination[] | 分播需求（多个目标仓） |
| pickRecords | PickRecord[] | 下架历史记录（批次追溯） |
| forkliftDriver | string | 绑定叉车司机 |
| status | TaskStatus | 待领取/下架中/分播中/待发运/已完成 |
| totalQty | number | 全量数量 |
| pickedQty | number | 已下架累计 |
| progress | number | 整体进度百分比 |

### PickLocation

每个下架来源库位。

| 字段 | 类型 | 说明 |
|------|------|------|
| location | string | 库位编码 |
| batchNo | string | 该库位上的批次 |
| availableQty | number | 可用库存 |
| pickedQty | number | 已下架量 |

### TaskDestination

每个分播目标。

| 字段 | 类型 | 说明 |
|------|------|------|
| targetWarehouse | string | 目标配送仓 |
| orderId | string | 关联调拨单号 |
| plannedQty | number | 计划量 |
| sortedQty | number | 已分播量 |

### PickRecord

每笔下架操作的历史记录（批次追溯的原始凭证）。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 记录 ID |
| location | string | 库位 |
| batchNo | string | 批次 |
| qty | number | 下架量 |
| allocations | {targetWarehouse, qty}[] | 该批次分到各仓的明细 |

### 3.2 交互

1. **合并任务预览** — 系统自动按 SKU+批次归组，展示各目标仓分配量
2. **任务派发** — 每个任务绑定一个司机，确认后进入执行状态
3. **执行监控** — 展示每个任务的状态、分播进度，可展开查看批次追溯
4. **单调拨单场景**：独有 SKU 展示为「独立任务/直派」，不等待合并

## 4. PDA 叉车司机 — 三步交互

### 4.1 任务总览

显示当前任务的所有信息：库位批次来源（已完成/进行中/待完成状态）、分播需求进度、历史记录。

```
┌────────────────────────────────┐
│ ‹ 返回    调拨拣货   合并任务   │
├────────────────────────────────┤
│ 高筋面粉 25kg/袋              │
│ 总计 1000袋  司机 刘海峰       │
│ 下架 900/1000  分播 430       │
│ ████████░░░░░░ 43%           │
│                                │
│ 下架来源（按库位逐批）          │
│ ┌ A-03-02-01  B01  600 ✓ ──┐ │
│ └──────────────────────────┘ │
│ ┌ A-03-02-02  B02  400 ⚡ ──┐ │
│ │ 300/400  [开始此库位下架]  │ │
│ └──────────────────────────┘ │
│                                │
│ 分播需求                       │
│ A仓 ████████░░ 200/300        │
│ B仓 █████░░░░░ 150/400        │
│ C仓 ███░░░░░░░  80/300        │
│                                │
│ ▶ 历史下架记录追溯              │
│  ├─ A-03-02-01|B01|600袋      │
│  │  → A200 B200 C200          │
│  └─ A-03-02-02|B02|300袋      │
│     → A70 B50 C80             │
└────────────────────────────────┘
```

**关键交互：**
- 每个库位展示批次号、可用量、下架进度
- 当前应操作的库位高亮，其余已完成显示 ✓
- 分播需求按目标仓展示进度条

### 4.2 下架

点击「开始此库位下架」进入：

```
┌────────────────────────────────┐
│ ‹ 返回  ① 下架      批次 B02   │
├────────────────────────────────┤
│ A-03-02-02                    │
│ 高筋面粉 25kg/袋  批次 B02     │
│                                │
│ 扫描 / 确认库位                 │
│ [A-03-02-02]                  │
│                                │
│ 下架数量                400    │
│ [400] [200] [100] [全量]       │
│                                │
│ [下架 400 袋，去分播 →]        │
└────────────────────────────────┘
```

**关键交互：**
- 库位自动填充（从任务获取），可扫描覆盖
- 数量快选按钮：全量、半量、1/4 量
- 确认后自动进入分播

### 4.3 顺序分播

每次只问一个仓，确认后自动进入下一个：

```
┌────────────────────────────────┐
│ ‹ 返回  ② 分播      批次 B02   │
├────────────────────────────────┤
│ 批次 B02 · 下架 400 袋         │
│ 已分 0，剩 400                 │
│                                │
│ ┌── 这批分到哪个仓？ ──────┐  │
│ │         A 仓             │  │  ← 当前目标（大号）
│ │      还需 100 袋         │  │
│ │                          │  │
│ │   [−]  [ 100 ]  [+]     │  │  ← +/- 调数量
│ │   10   50   全部 100     │  │  ← 快选
│ └──────────────────────────┘  │
│                                │
│ 各仓剩余:                       │
│ A仓 还需 100 ← 正在分          │
│ B仓 还需 250                   │
│ C仓 还需 220                   │
│                                │
│ 进度: 100 / 400 袋             │
│                                │
│ [确认 100 袋 分到 A 仓]        │
└────────────────────────────────┘
```

确认后自动切换到下一个有需求的仓：

```
│ ┌── 下一个 ──────────────────┐ │
│ │         B 仓             │  │
│ │      还需 250 袋         │  │
│ │                          │  │
│ │   [−]  [ 150 ]  [+]     │  │
│ └──────────────────────────┘  │
│                                │
│ 进度: 250 / 400 袋             │
│                                │
│ [确认 150 袋 分到 B 仓]        │
```

最后一个仓分完 → 全部完成 → 回到总览。

**关键规则：**
- 每次只展示 1 个仓，聚焦当前动作
- +/- 按钮对应物理搬货动作（一次搬一批到暂存区）
- 快选按钮快速填入常见量
- 当前仓可分配的最大量 = min(该仓剩余需求, 本批剩余未分数量)
- 全部分完前禁止跳过

## 5. 单调拨单场景

当只有 1 个调拨单（独有 SKU）：

- PC 侧展示为「独立任务」，标记「直派」
- 不等待合并，直接派给司机
- PDA 流程不变：下架 → 分播，但分播只有 1 个目标仓
- 输入数量 = 下架数量，一次确认即完成

## 6. 批次追溯机制

**追溯链：**

```
PickRecord ① → A-03-02-01 | 批次 B01 | 600袋
                 → A仓 +200  B仓 +200  C仓 +200

PickRecord ② → A-03-02-02 | 批次 B02 | 300袋
                 → A仓 +70  B仓 +50  C仓 +80

汇总 → A仓 270  B仓 250  C仓 280
```

即：每个下架记录包含了「哪个库位、哪个批次、下架多少、分别分到了哪些仓各多少」，形成完整的可追溯链路。

PC 监控页面可展开查看；PDA 总览页底部也可查看历史记录。

---

## 7. 边界情况

| 情况 | 处理 |
|------|------|
| 多个库位同 SKU 不同批次 | 按库位逐批操作，每批独立下架+分播 |
| 同一库位多次下架 | 支持，记录多次 pickRecord |
| 分播时数量不足 | 输入框 max = min(仓剩余, 本批未分) |
| 全部分完还有剩余 | 不允许 — 分配总数必须等于下架总数 |
| 1 个调拨单 | 直派模式，不等待合并 |
