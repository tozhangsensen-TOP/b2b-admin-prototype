## 1. 需求背景

零散干货调拨场景下，原有拣货作业只能「单端、单个订单逐一操作」，单人串行下架 + 搬货分拣，效率瓶颈明显。业务需要：

1. **合单 / 合车 / 波次** 可配置，把零散调拨单合并成集中拣货任务；
2. **双人两端协同**：叉车司机负责下架，分拣员同步跟进搬货播种，两端并行；
3. **现场无干线**：集中拣货后由不同车次点对点拉到各配送仓（**无「线路/干线」概念**，单号不再按线路命名，波次单号格式为 `BC + 10 位数字`，如 `BC0123123132`）。

本 PRD 聚焦上述链路中的 **手持 PDA 作业端**（双端：叉车端下架 + 分拣端播种），并补充 **分拣端任务拆分** 新需求。

---

## 2. 业务目标与价值

| 目标 | 说明 |
|---|---|
| 下架与播种并行 | 叉车司机下架与分拣员播种同时开展，打破单人串行瓶颈 |
| 见货分货、按批次追溯 | 分拣员面对实物 SKU/批次，下拉选批次后按仓播种，全程批次可追溯 |
| 规则前端可配 | 合单/合车/波次/拣货模式/领取规则全部前端配置，不外置硬编码 |
| 大任务可拆分并行 | 分拣端支持按 SKU 数量拆分，大单多分拣员并行作业（新增） |

---

## 3. 名词解释

| 名词 | 说明 |
|---|---|
| 波次 | 调拨单按规则合并后生成的拣货批次，单号 `BC + 10 位数字` |
| 车次 | 波次按合车数打包成的运输单元，单号 `VC + 3 位数字`（如 `VC001`） |
| 调拨拣货任务 | 一个车次下挂的拣货任务，单号 `TP-{波次}-{序号}` |
| 叉车端 | 叉车司机使用的下架作业端 |
| 分拣端 | 分拣员使用的播种作业端 |
| 见货分货 | 分拣员按眼前实物 SKU，选批次后分到各仓的播种方式 |
| 批次 | 货品下架来源批次（如 `B20260803`），下架与播种按 `目标仓 × 批次 × SKU` 精确匹配 |

## 4. 功能概述

双端 PDA 以「手机框」形态呈现（与既有 `picking-pda-h5`、`transfer-dispatch` 司机 PDA 视觉一致），顶部用分段控件在 **叉车端 / 分拣端** 间切换。两端共享同一任务的任务概览卡，确保信息对齐。

```
┌─────────────────────────────┐
│  09:41   WiFi  🔋86%         │  ← 状态栏（示意）
│  ←  叉车端 · 下架   [VC001]  │  ← 顶栏：返回 / 标题 / 车次角标
│  [ 叉车端 | 分拣端 ]         │  ← 分段切换
│  ─────────────────────────  │
│  任务号 [ TP-BC…-001 ▾ ]     │  ← 任务选择
│  ┌─ 任务概览卡 ───────────┐  │
│  │ 高筋面粉 25kg   [模式]  │  │
│  │ TP-BC…-001 · 车次 VC001 │  │
│  │ 总需求 1000 需求仓数 3  │  │
│  │ 下架 80%  播种 52%      │  │
│  │ 需求仓：A仓 B仓 C仓     │  │
│  └─────────────────────────┘  │
│  （叉车端内容 | 分拣端内容）  │
└─────────────────────────────┘
```

## 5. 详细功能需求

### 5.1 PDA 框架与导航

| 项 | 规则 |
|---|---|
| 载体 | 移动端手机框（max-width 430px，圆角外壳 + 状态栏） |
| 顶栏 | 返回箭头（回到「调拨拣货」作业中心）、标题（叉车端·下架 / 分拣端·播种）、车次角标 `Badge` |
| 端切换 | 顶部分段控件 `叉车端 / 分拣端`，切换不影响已选任务 |
| 任务选择 | 下拉 `Select`，选项 `taskNo · vehicleNo` |

### 5.2 任务概览卡（两端共享）

| 字段 | 来源 |
|---|---|
| 主标题 | 任务主 SKU 名；多 SKU 时显示「SKU1 等 N 个 SKU」 |
| 副标题 | `taskNo · 车次 vehicleNo` |
| 模式标签 | `pickModeBadge`（车统边拣边播=蓝 / 车统后按店播种=黄 / 直接SKU播种=灰） |
| 总需求量 | `sorterLines.planned` 求和 |
| 需求仓数 | `sorterLines.dest` 去重数 |
| 下架% / 播种% | `forkliftProgress` / `sorterProgress` |
| 需求仓明细 | `sorterLines.dest` 去重列表 |
| 总进度条 | `(下架% + 播种%) / 2` |

### 5.3 叉车端 · 下架（`ForkliftEnd`）

| 项 | 规则 |
|---|---|
| 列表 | 下架来源，按「库位逐批」展示 `forkliftLines`（库位、批次、SKU 名、已下架/计划） |
| 操作 | 点击待下架行 → 展开：扫描/确认库位（只读，显示库位码）、本次下架数量、快捷按钮（½ / ¼ / 全量）、确认下架 |
| 数量约束 | 本次下架 ≤ 该行剩余计划量；下架量达计划 → 状态置「已下架」 |
| 联动 | **车统边拣边播** 模式下，确认下架按钮附「· 同步播种」文案，且下架时按 `applyForkliftPick` 自动按比例推进分拣端 `sorterLines` |
| 人员 | 底部显示叉车司机 `forkliftDriver` |

### 5.4 分拣端 · 播种（`SorterEnd` + `SkuSeedCard`）

| 项 | 规则 |
|---|---|
| 锁定规则 | **车统后按店播种** 模式下，若叉车端未全部下架，分拣端锁定（显示锁形提示，禁止播种） |
| 分组 | `sorterLines` 按 `sku` 分组，每个 SKU 一个 `SkuSeedCard` |
| 批次选择 | 每张卡顶部「本次批次（见货选择）」下拉，可选项 = `forkliftLines` 中该 SKU 且已下架量 `> 0` 的批次；无可用批次则提示「该 SKU 暂无已下架批次，无法播种」 |
| 分仓播种 | 选中批次后，逐仓展示「需 / 已 + 数字输入 + 剩余 N 快捷填充」 |
| 批量确认 | 「确认播种 → 批次 X」一次性把各仓 `> 0` 的输入按 `dest + sku + batchNo` 精确匹配写入（修复过多批次同加的 bug） |
| 人员 | 底部显示分拣员 `sorter` |

### 5.5 双人两端联动规则

| 拣货模式 | 叉车端 | 分拣端 |
|---|---|---|
| 车统边拣边播 | 正常下架 | 下架时同步按比例播种（实时联动） |
| 车统后按店播种 | 正常下架 | **下架全部完成前锁定**，完成后才允许播种 |
| 直接SKU播种 | 正常下架 | 不依赖店维度，按 SKU 直接播种到仓 |

任务状态机：`待领取 → 进行中 → 部分完成 → 已完成`（下架与播种任一有进度即「进行中」，播种达 100% 且下架 100% 即「已完成」）。

## 6. 新增需求：分拣端任务拆分（按 SKU 数量拆分）

### 6.1 背景

部分调拨拣货任务体量大（多 SKU、各仓计划数量大），单分拣员串行播种耗时长。为进一步提升吞吐，分拣端需支持 **将任务按 SKU 数量拆分** 成多个子任务，由多名分拣员并行作业，或按数量均衡分配工作量。

### 6.2 触发入口

| 入口 | 位置 |
|---|---|
| PDA 分拣端 | 任务详情页新增「拆分任务」按钮（仅任务为 `待领取` / `进行中` 且未全部播种时可用） |
| 作业中心 | 监控表行操作「拆分」（同条件） |

### 6.3 拆分方式

本次需求核心为 **按 SKU 数量拆分**，同时保留按 SKU 归组的辅助方式：

| 拆分方式 | 规则 |
|---|---|
| **按 SKU 数量拆分（主）** | 设定「单子任务单 SKU 数量上限」或「拆分数 N」，系统将每个 SKU 在各仓的计划数量按比例摊分到子任务，保证「各子任务之和 = 原任务」 |
| 按 SKU 归组（辅） | 将不同 SKU 整组分配给不同子任务（适合 SKU 间无交叉的清晰分组） |

**按 SKU 数量拆分算法（示例）**

假设某任务仅 1 个 SKU（高筋面粉），各仓计划：A 仓 300、B 仓 240、C 仓 160，合计 700。
设定单子任务单 SKU 上限 = 300：

- 子任务 1：A 300（满）
- 子任务 2：B 240 + C 60（=300）
- 子任务 3：C 100（剩余）

> 多 SKU 时，每个 SKU 独立按上限切分后组合进子任务；同一 `(SKU, 批次, 目标仓)` 的数量不跨任务重复、不丢失。

### 6.4 交互流程（PDA 分拣端）

```
任务详情 → 点「拆分任务」
  → 弹出拆分面板
      · 拆分方式：按SKU数量 / 按SKU归组
      · 参数：单SKU数量上限 [ 300 ] ｜ 或 拆分数 [ 3 ]
      · 预览：原 700 件 → 子任务1 300 / 子任务2 300 / 子任务3 100
  → 确认拆分
      · 原任务置「已拆分」
      · 生成 N 个子任务（同车次、同波次、同拣货模式、继承批次）
      · 子任务进入分拣端任务列表，可分别指派分拣员
```

### 6.5 业务约束

| 约束 | 说明 |
|---|---|
| 可拆状态 | 仅 `待领取` / `进行中` 且存在未播种数量的任务可拆 |
| 数量守恒 | 拆分后所有子任务各仓、各批次计划数量之和 = 原任务 |
| 不拆叉车端 | 拆分仅作用于 **分拣端播种**；叉车端下架仍按原任务一次完成（下架是实物整批下，不分） |
| 锁定继承 | 子任务继承父任务拣货模式；若父为「车统后按店播种」，子任务同样需待叉车端下架完成后方可播种 |
| 不可再拆 | 已拆出的子任务不再支持二次拆分（避免无限裂变） |
| 批次一致 | 子任务 `sorterLines` 的 `batchNo` 沿用父任务的已下架批次 |

### 6.6 数据模型变更建议

在 `TransferPickingTask` 增加字段：

```ts
export type TransferPickingTask = {
  /* 现有字段不变 … */
  parentTaskNo?: string;   // 若由拆分生成，指向父任务 taskNo
  splitGroupId?: string;   // 同一拆分组的子任务共享，便于聚合展示
  isSplit?: boolean;       // 标记是否已被拆分（父任务）
};
```

任务状态枚举新增：

```ts
export type TaskStatus = "待领取" | "进行中" | "部分完成" | "已完成" | "已拆分";
```

`TransferPickingTask` 列表渲染时，按 `splitGroupId` 分组、父任务折叠展示子任务；PDA 分拣端任务下拉中，子任务以「`taskNo`（子·分拣员）」形式列出。

## 7. 非功能性需求

| 项 | 要求 |
|---|---|
| 离线容错 | PDA 断网时本地缓存本次操作，恢复后回传（原型阶段可仅做本地状态） |
| 操作确认 | 下架/播种/拆分均二次确认，防误触 |
| 性能 | 单任务 SKU 数 ≤ 50、行数 ≤ 300 时列表无卡顿 |
| 一致性 | 双端进度实时对齐，避免两端看到的完成度不一致 |

## 8. 验收标准

- [ ] 叉车端可逐库位批次下架，车统边拣边播模式下分拣端同步推进
- [ ] 分拣端按 SKU 分组、下拉选批次、逐仓输入数量后一次性播种，批次精确匹配无串批
- [ ] 车统后按店播种模式下，分拣端在下架未完成前锁定
- [ ] 任务概览卡正确展示 SKU 名、总需求量、需求仓数、需求仓明细与进度
- [ ] 波次单号 `BC + 10 位`、车次 `VC + 3 位`，无「线路/干线」展示
- [ ] **（新增）** 分拣端「拆分任务」可按 SKU 数量将任务拆成多个子任务，子任务数量之和 = 原任务，且可分别指派分拣员并行作业
