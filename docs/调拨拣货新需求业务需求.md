# 调拨拣货新需求业务需求

| 项目 | 内容 |
|---|---|
| 需求名称 | 零散干货调拨拣货合单合车及双人协同作业优化 |
| 业务场景 | 零散干货调拨任务拣货、下架、分拣、播种 |
| 提报对象 | IT系统建设/优化 |
| 需求类型 | 业务需求 |
| 关联范围 | 调拨拣货作业中心、调拨拣货规则配置、调拨拣货PDA |

## 1. 需求背景

目前零散干货调拨任务在分拣任务模式下，拣货作业主要按单端、单个订单逐一执行。叉车司机下架、分拣人员搬货分拣存在明显串行等待，现场作业效率受单人操作节奏影响较大。

随着调拨单量增加，业务现场需要将多个零散调拨单按照一定规则进行合单、合车和波次组织，并支持叉车司机与分拣人员在两个作业端同时开展工作。叉车司机负责按库位、批次下架，分拣人员根据下架实物同步进行搬货分拣或播种，实现下架与分拣并行，提高零散干货调拨作业效率。

## 2. 业务目标

1. 支持零散干货调拨单按业务规则自动或人工合并，形成适合现场集中作业的合单、合车、波次任务。
2. 支持叉车端下架与分拣端播种双人协同作业，减少下架完成后再分拣的等待时间。
3. 支持不同现场作业方式，包括车统后按店播种、车统边拣边播、直接SKU播种。
4. 支持按车或按波次领取任务，并允许PC端按人员进行任务指派。
5. 支持多人领取和执行分拣任务，满足大批量调拨任务并行处理需要。

## 3. 现状问题

1. 单个调拨单逐一作业，零散订单无法有效集中处理，现场重复走动、重复下架较多。
2. 下架和分拣动作串行，分拣人员需要等待叉车司机完成下架后再开始处理，整体作业周期长。
3. 合单、合车、波次等规则缺少业务前端可配置能力，现场货量变化时调整不够灵活。
4. 任务领取维度偏单一，无法适配按整车、整波次集中领取和多人协同执行。
5. 大任务只能由单人持续操作，无法有效拆分给多名分拣人员并行处理。

## 4. 业务需求范围

本次需求覆盖零散干货调拨任务从任务创建、合单合车、波次生成、任务领取、叉车下架、分拣播种到完成回传的业务流程。

不包含具体页面样式、按钮位置、字段交互细节等PRD内容；具体系统页面设计由IT在产品方案阶段进一步细化。

## 5. 核心业务诉求

### 5.1 支持合单规则业务可配置

业务需要在调拨分拣任务创建规则中配置是否启用合单。启用后，系统可按照业务设定的合并维度，将满足条件的零散调拨单合并为一个集中拣货任务。

合单规则需支持以下业务能力：

1. 可配置是否启用合单。
2. 可配置合并维度，例如按SKU、按SKU+批次、按目标仓等维度合并。
3. 可配置自动合单条件，例如达到指定单量后自动合并生成任务。
4. 支持业务人员手动选择需要合并的调拨单范围，用于适配现场作业场地、货量、人员安排等实际情况。
5. 合单后需保留原始调拨单关系，便于后续追溯每个调拨单的执行情况。

### 5.2 支持合车和波次规则业务可配置

业务需要在调拨分拣任务创建规则中配置合车数和波次规则。系统根据波次和合车规则，将合并后的调拨任务组织成车次任务，方便现场按车集中下架、搬货和分拣。

合车和波次规则需支持以下业务能力：

1. 可配置是否启用合车。
2. 可配置每车合并任务数或单据数上限，即合车数。
3. 支持按波次合车，必要时也可扩展按配送方向或现场作业分区合车。
4. 支持满车后自动生成车次任务。
5. 支持未满车时由业务人员手动确认是否生成车次。
6. 支持按时间窗或单量形成波次，满足不同作业节奏。
7. 生成后的波次、车次、任务之间需有关联关系，便于PC端监控和PDA端领取。

### 5.3 支持双人两端协同作业

分拣任务需从单人串行模式调整为双人两端协同模式。一个调拨拣货任务同时拆分为叉车端和分拣端两个作业环节，两端独立操作、进度联动。

叉车端业务要求：

1. 叉车司机负责调拨货品下架。
2. 下架需按库位、批次、SKU维度执行。
3. 下架时需记录实际下架数量。
4. 下架进度需实时反馈给分拣端和PC端。

分拣端业务要求：

1. 分拣人员负责跟随下架实物进行搬货、分拣和播种。
2. 分拣端需根据目标仓、门店或SKU维度完成播种。
3. 分拣端需识别当前可分拣的SKU和批次，避免未下架货品提前播种。
4. 分拣进度需实时反馈给叉车端和PC端。

双端联动要求：

1. 同一任务下，叉车端和分拣端共享任务号、波次、车次、SKU、批次和目标仓信息。
2. 叉车下架完成的数量应成为分拣端可操作数量的来源。
3. 下架、分拣任一环节发生异常时，需能在任务进度中体现，避免任务被误判完成。
4. 任务需同时记录下架完成率和分拣完成率，全部完成后任务才可关闭。

### 5.4 支持多种拣货和播种方式

为适配不同作业现场，调拨拣货任务需支持以下拣货模式：

1. 车统后按店播种：先完成整车或整任务下架，再由分拣人员按门店或目标仓播种。
2. 车统边拣边播：叉车司机下架过程中，分拣人员同步跟进搬货和播种，实现并行作业。
3. 直接SKU播种：分拣人员按SKU直接播种到目标仓，不强制按门店聚合。

业务要求系统能够在任务创建时带入默认拣货模式，也允许业务根据现场情况选择适合的拣货模式。

### 5.5 支持任务领取和指派规则

调拨拣货任务需适配合单、合车和波次后的领取方式，不再仅按单个订单领取。

任务领取需支持以下业务能力：

1. 支持按车领取，即现场人员领取某一车次下的全部或部分调拨拣货任务。
2. 支持按波次领取，即现场人员领取某一波次下的合并任务。
3. 支持领取顺序可选，例如先到先得、按优先级、按业务设定顺序。
4. 支持PC端指派叉车司机和分拣人员。
5. 支持叉车司机和分拣人员分别领取同一任务的不同作业端。
6. 支持多人领取分拣任务，满足大单或多SKU任务并行处理。

### 5.6 支持多人分拣协同

对于货量较大、SKU较多或目标仓较多的调拨任务，业务需要支持多名分拣人员同时参与。

多人分拣需满足以下业务要求：

1. 同一波次或同一车次下，可由多名分拣人员领取分拣任务。
2. 系统需避免多人重复分拣同一SKU、批次、目标仓的同一数量。
3. 可按SKU、目标仓、任务量或系统拆分规则分配给不同分拣人员。
4. 分拣完成情况需能汇总回原波次、车次和调拨任务。
5. PC端需能查看每名分拣人员的领取和完成情况。

## 6. 业务流程建议

1. 调拨单生成后进入待创建分拣任务池。
2. 系统根据合单规则判断可合并的调拨单。
3. 达到自动合单条件时，系统自动生成合单任务；未达到或业务需要调整时，由业务人员手动选择合并范围。
4. 合单任务进入波次池，系统按照波次规则生成波次。
5. 系统按照合车规则将波次内任务打包成车次，满车自动生成，未满车可人工确认。
6. 任务生成后，叉车司机和分拣人员可按车或按波次领取，PC端也可提前指派人员。
7. 叉车司机在PDA端按库位、批次、SKU执行下架。
8. 分拣人员在PDA端根据拣货模式同步或后置进行播种。
9. 系统实时更新下架进度、分拣进度、人员状态和任务状态。
10. 下架和分拣均完成后，调拨拣货任务完成，并回传执行结果。

## 7. 业务规则

1. 合单任务必须保留原调拨单明细，不允许合并后丢失原单追溯关系。
2. 合车任务必须能追溯所属波次、车次和任务明细。
3. 同一任务的下架数量不得超过计划下架数量。
4. 分拣播种数量不得超过已下架可分拣数量和目标仓计划数量。
5. 车统后按店播种模式下，分拣端原则上需等待叉车端完成下架后再开始播种。
6. 车统边拣边播模式下，分拣端可跟随已下架数量同步播种。
7. 直接SKU播种模式下，系统需支持按SKU直接分配到目标仓。
8. 任务完成判断需同时满足下架完成和分拣完成。
9. 多人分拣时，系统需控制任务分配边界，避免重复领取、重复播种或数量冲突。
10. 业务规则应通过前端或后台配置维护，避免写死在系统程序中。

## 8. 角色与职责

| 角色 | 业务职责 |
|---|---|
| 业务计划/仓库管理人员 | 配置合单、合车、波次、领取、拣货模式规则，确认手动合并范围 |
| PC端调度人员 | 查看任务池，确认合单合车结果，按车或波次指派叉车司机和分拣人员 |
| 叉车司机 | 在PDA端领取或执行下架任务，按库位、批次、SKU完成下架 |
| 分拣人员 | 在PDA端领取或执行分拣任务，按目标仓、门店或SKU完成播种 |
| IT系统 | 提供规则配置、任务生成、双端联动、多人领取、进度汇总和结果回传能力 |

## 9. 业务价值

1. 实现下架和搬货分拣并行作业，打破单人串行操作瓶颈，提升零散干货调拨分拣处理效率。
2. 通过合单、合车和波次组织，减少重复下架、重复行走和重复分拣，提高现场集中作业能力。
3. 规则全部支持业务前端配置，不依赖硬编码，适配不同货量、场地、人员和作业节奏。
4. 支持按车、按波次集中领取和PC端指派，提升现场任务调度灵活性。
5. 支持多人分拣协同，降低大任务积压风险，提高高峰期调拨处理能力。
6. 保留原单、批次、库位、目标仓和人员操作记录，提升作业追溯能力。

## 10. 期望IT支持事项

1. 提供调拨拣货规则配置能力，覆盖合单、合车、波次、拣货模式、领取方式和PC指派规则。
2. 提供调拨单自动合并和人工选择合并能力。
3. 提供按波次、按车生成调拨拣货任务能力。
4. 提供叉车端和分拣端双PDA作业能力。
5. 提供双端进度联动和任务状态汇总能力。
6. 提供按车、按波次领取，以及PC端指派人员能力。
7. 提供多人分拣领取、拆分和汇总能力。
8. 提供任务执行结果回传和追溯查询能力。

## 11. 初步验收口径

1. 业务人员可以配置合单、合车、波次、拣货模式和领取规则。
2. 多个零散调拨单可以按规则生成合单任务，并进一步形成波次和车次。
3. 叉车司机和分拣人员可以分别在PDA端执行同一调拨拣货任务的下架和分拣环节。
4. 系统可以支持车统后按店播种、车统边拣边播和直接SKU播种三种作业模式。
5. 任务可以按车或按波次领取，PC端可以指派叉车司机和分拣人员。
6. 同一车次或波次下可支持多名分拣人员领取并行作业。
7. 下架进度、分拣进度和任务总状态可以实时汇总展示。
8. 任务完成后，可以追溯原调拨单、波次、车次、SKU、批次、库位、目标仓和作业人员。

## 12. 待确认事项

1. 合单维度最终以按SKU、按SKU+批次、按目标仓中的哪些维度为准。
2. 合车数按调拨单数、任务数、件数、体积或车辆容量中的哪一种作为主控制口径。
3. 波次生成规则以时间窗为主，还是以单量为主。
4. 多人分拣任务是否需要支持系统自动拆分，还是仅支持人工指定分配。
5. 直接SKU播种是否需要保留门店维度展示。
6. 调拨拣货完成后，结果回传至哪个下游系统或单据状态节点。
